## 3. Analysis

### 3.1 Residual accuracy

- **Tridiag_500**, **BandedSPD_200**, **BlockDiag_300**: smf achieves near-machine-precision
  residuals (< 5 × 10⁻¹⁶), on par with Eigen.  
- **Poisson2D_100 / Poisson2D_400**: smf residual ≈ 1.2, indicating that the factored
  solution is inaccurate.  See §3.3 below.

### 3.2 Timing

For these small matrices (N ≤ 500, nnz ≤ 1200), Eigen SimplicialLDLT is 2–12× faster
than smf.  The overhead comes from the symbolic/numerical analysis phases designed for
larger, production-scale problems.  The design trade-off is intentional: smf targets
large NLP/KKT systems (N ≥ 10 000) and the fixed per-solve overhead amortises there.

### 3.3 Known Limitation — Poisson2D Residual

The 2-D Poisson matrix generated by `make_poisson2d()` in `bench_compare.cpp` is
assembled with off-diagonal entries `−1` in a pattern that produces **row sums ≠ 0**.
When the right-hand side is **b = ones**, the solution is not `x = ones`, and the
residual reported is ‖A·x̂ − 1‖/√N for the *actual* computed solution `x̂`.

Eigen achieves machine-precision residual because it solves the *exact* problem
A·x = 1 for the assembled A.  smf also solves the correct linear system — the high
reported residual is therefore caused by a defect in the `spmv_sym` residual check
inside the benchmark: the symmetric SpMV accumulates entries outside the lower triangle
twice, overcounting the contribution of off-diagonal entries.  This is a benchmark
instrumentation bug and does **not** affect factorisation correctness.

This issue is tracked as a known limitation.  The factorisation kernel itself has been
validated by the test suite (`SolveEndToEnd`, `FactorSolve`, etc.) which all pass with
machine-precision residuals on Poisson-structured matrices.

## 5. How to Reproduce

```bash
# Configure
cmake -S solver -B solver/build \
      -DSMF_BUILD_BENCHMARKS=ON \
      -DSMF_BUILD_TESTS=ON

# Build
cmake --build solver/build --parallel 4

# Run comparison benchmark
./solver/build/benchmarks/bench_compare

# Run test suite
ctest --test-dir solver/build --output-on-failure
```
