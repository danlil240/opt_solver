# IPM mode: early abort, realized-order re-analysis, static modes, and the default decision

**Date:** 2026-10-26
**Branch:** `feat/ipm-mode`
**Spec:** `docs/superpowers/specs/2026-10-26-ipm-mode-design.md`. **Roadmap:** Horizon 1, item 2 of `docs/roadmap.md`.

## Result

All three features are built and tested, and all of them stay **off by default**. Each one failed its gate. On the held-out models the plugin behaves exactly as plain smf.

| feature | env flag (opt-in) | tuning gate | held-out gate | default |
|---|---|---|---|---|
| 1. inertia learning + early abort | `SMF_IPM_ABORT=1` | FAIL: chain log diverged; best saving 3.6% | FAIL: logs identical on 6/6, but no saving (no front skipped) | **off** |
| 2. re-analysis from the realized order | `SMF_IPM_REANALYSE=1` | FAIL: iteration geomean 0.939, out of band (the wins were path changes) | FAIL: wall geomean 1.017 > 1 (iterations identical) | **off** |
| 3a. static mode Fallback (hybrid accounting) | `SMF_IPM_STATIC=fallback` | smoke only (elec: different optimum) | FAIL: new failure (case9241 max_iter), iteration geomean 2.75 | **off** |
| 3a'. Fallback, all-zero accounting | `+ SMF_IPM_STATIC_ZERO=1` | smoke only (elec: Error in step computation) | FAIL: 4 new failures (Restoration Failed) | — |
| 3b. static mode Regularized (hybrid) | `SMF_IPM_STATIC=regularized` | smoke only (case118: same iterations, 4.6× IPOPT time without function evaluations, 2.3× process wall) | FAIL: iteration geomean 1.23, wall geomean 4.74 | **off** |
| 3b'. Regularized, all-zero accounting | `+ SMF_IPM_STATIC_ZERO=1` | smoke only | FAIL: new failure (case9241 timeout), iteration geomean 2.10 | — |

Static default is therefore **Off**, not Regularized: neither static mode passed the held-out outcome gate. The accuracy replay is a second requirement that only a mode passing the outcome gate must also meet, so it decided nothing here. It was still run and is reported below as information.

`IpmControl`'s own defaults follow the same decision: `abort_on_wrong_inertia` and `reanalyse` are `false` (the spec's struct had the abort on), so a direct `IpmSession` user opts in, as the plugin's env flags do. Every departure from the spec is listed in "Rulings and spec deviations" below.

The hard corpus has 16 IPOPT models: 8 PGLib-OPF cases (through Egret) and 8 COPS problems (Pyomo). Each model is tagged `split: tuning` (10) or `split: heldout` (6) in `benchmarks/manifests/ipopt_hard.json`. Full KKT sequences are captured with `--keep all`, capped at 1000 factorizations per analysis, in `benchmarks/fixtures/ipopt_hard/`. Baseline: `benchmarks/results/ipopt_hard_baseline_t1.json`. Full table: `benchmarks/results/phase0_exit.md`.

- **Tuning (10):** pglib case118_ieee, case500_goc__api, case2869_pegase, case4661_sdet; cops glider_400, catmix_800, chain_800, pinene_400, steering_800, elec_200.
- **Held-out (6):** cops rocket_800 and polygon_200; pglib case300_ieee, case1354_pegase, case2000_goc__sad, case9241_pegase.
- **Phase 0 verdict: PASS.** All 10 tuning models qualify under the plan's either-criterion rule. Four of them qualify on inertia corrections (glider, chain, steering, elec). The delay criterion turned out to be non-discriminating: every ACOPF case delays ~12% of n per factorization.
- **Robustness gap found in Phase 0.** smf is worse than MA27 inside IPOPT on two nonconvex COPS models:
  - cops_chain_800 hits max_iter 3000, while MA27 converges in 1475 iterations;
  - cops_elec_200 needs 304 iterations against MA27's 157.

  On chain, the delays per factorization (36,149) are 6× n: columns are re-delayed through many fronts in a cascade.
- **The held-out set is mild.** smf matches MA27's iteration count on 5 of 6 models (case2000_goc__sad: 55 vs 53). Inertia corrections occur only on case2000_goc__sad (18), polygon (29), rocket (4) and case9241 (3). The held-out gates therefore mostly measure harm, not benefit.

### acopf_grid_160 triage: a harness stopping-rule defect, not an smf defect

acopf_grid_160 replayed as `Inaccurate` (omega 1.4e-6 at step 4, with max|A| = 2.9e11).

- **Cause:** the harness refinement's stopping rule was normwise only: it stopped once eta ≤ 1e-14. With ‖A‖ ~ 1e11, eta is ~1e-19 already at sweep 0, so no correction ever ran. Meanwhile rows with small entries carried a componentwise error that the gate (omega ≤ 1e-8) rejects.
- **Evidence:** one more correction solve takes omega from 1.4e-6 to 1.7e-15.
- **Fix:** the stopping rule in `solver/benchmarks/common/replay_refine.hpp` now requires both eta ≤ 1e-14 and omega ≤ 1e-10, and stops on stagnation. The regression test is `Refinement.Acopf160`.
- **Unchanged:** the u = 1e-8 track threshold and the accuracy gates.
- **Scope:** the library's `refine()` is not on this replay path. This was harness refinement only.

Full bisection table: `phase0_exit.md`.

## Feature 1: inertia learning and early abort

The session learns IPOPT's expected negative count from the last factor it solved with. It stops a factorization once the running negative count exceeds that expectation (`InertiaExceeded`, reported to IPOPT as flag 0 with the partial count). The gate requires identical IPOPT logs on every model, and a factorization-time saving of at least 5% on a model with inertia corrections.

## Feature 2: re-analysis from the realized pivot order

After an accepted factor that delayed more than 1% of n, the session re-analyses from the realized elimination order and its 2×2 pairs. It adopts the new analysis only if the predicted flops do not exceed those of the last factor. Probation reverts the analysis if delays grow.

The gate is the outcome gate:
- iteration geomean within [0.95, 1.05];
- no new failures;
- wall geomean ≤ 1, over models whose base wall time is ≥ 1 s.

## Feature 3: static modes

- **Fallback:** threshold pivoting with delays, but a column that would reach a root unpivoted, or a front over its delay budget, gets a static pivot at 1e-8·max|A| instead.
- **Regularized** (quasidefinite):
  - +ρ on primal rows and −ρ on constraint rows, with ρ = 1e-8·max|A| after scaling;
  - AMD order, 1×1 pivots, no delays;
  - every full solve is refined against the unregularized matrix.

### Accounting rulings: hybrid vs all-zero

The spec reports every raised pivot as a **zero** eigenvalue, so that IPOPT's δ_c safeguard takes over. That rule provably breaks IPOPT on cops_elec_200:
- the static tolerance (1e-8·max|A|) grows with IPOPT's δ_x;
- the constraint pivots (≈ −1/δ_x) are then raised and reported as zeros;
- δ_c cannot lift them, IPOPT keeps raising δ_x, and fails with "Error in step computation" at iteration 77.

Both static modes therefore use **hybrid accounting** by default, a spec deviation (see "Rulings and spec deviations"):
- a raised pivot whose original |d| is below the small-pivot threshold (a genuine zero, e.g. from dependent constraints) counts as zero;
- a nonzero-but-tiny raised pivot counts by its kept sign;
- `SMF_IPM_STATIC_ZERO=1` keeps the spec's all-zero rule for comparison.

Why both static modes are slow and unstable on this corpus:

- **Fallback reports zero eigenvalues on nonsingular KKT matrices.** On case300, Off factors every stored matrix with inertia (5540, 5415, 0). Fallback, on the same values, statically pivots ~150 columns at the root and reports 38 zeros (factor 1 of the IPOPT run matches the replay exactly). Those columns are exact zeros at the moment they reach the root, so even hybrid accounting counts them as zero. IPOPT answers with δ_c corrections, and the path degrades: case300 36→255 iterations, case9241 to max_iter with 12.6 M static pivots over 3011 factorizations.
- **Regularized pays for refinement and corrections.** Every full solve refines against the unregularized matrix (backsolve time 0.275 → 11.8 s on case2000). It also triggers many more inertia corrections (case2000: 18 → 142; polygon: 29 → 51). The fill is *smaller* with AMD and no delays (case2000 L 1.06 M → 0.87 M), so the slowdown is not in the factor size.
- **The row classification is not the cause of the extra corrections.** Regularized mode freezes its row classes at the first factorization (zero or missing diagonal = constraint row). Replaying the first stored step of each held-out fixture through an `IpmSession` in Regularized mode and counting `row_is_constraint`:

  | model | KKT n | n_x | n_s | m = m_eq + m_ineq | classified constraint | x / s rows misclassified | c / d rows misclassified |
  |---|---|---|---|---|---|---|---|
  | pglib_opf_case2000_goc__sad | 87432 | 29418 | 14532 | 28950 + 14532 = 43482 | 43482 | 0 | 0 |
  | cops_polygon_200 | 40600 | 400 | 20099 | 2 + 20099 = 20101 | 20101 | 0 | 0 |

  m is IPOPT's constraint count from its log ("Total number of equality constraints" + "inequality constraints"). IPOPT's KKT is [x, s, c, d] with one slack per inequality, so n = n_x + n_s + m (87432 and 40600, as captured), and the classes match the blocks row by row: every x and s row has a positive diagonal (W + Σ), every c and d row an exact zero. The first factor of each smf_reg run has the matching inertia (43950, 43482, 0) and (20499, 20101, 0). Each run used one session, so the classes never changed. The corrections come from the mode itself: on case2000, 137 of 305 smf_reg factorizations report more than m negatives, 73 of them with static pivots (raised pivots counted by their kept sign) and 64 without any. The path is also different (102 vs 55 iterations). Polygon has no static pivots at all; its run went to a different optimum (61 iterations), at 0.84 corrections per iteration against smf's 0.73.

### Accuracy replay (information; no variant passed its outcome gate)

`bench_replay` now routes smf through `IpmSession` with:
- `--ipm-static off|fallback|regularized` and `--ipm-static-zero`;
- `--seq-steps all`, which replays every stored factorization;
- `--ordering auto_parallel`, the plugin's ordering.

In this mode a factor the session reports as singular is skipped, not solved: IPOPT rejects such a factor and refactors with δ_c, and never solves with it. Results: `benchmarks/results/ipm_heldout_replay_t1.json`.

Two caveats:
- **The stored sequences come from the Off capture run,** so they are not the matrices IPOPT feeds a static mode.
- **IPOPT's real scaling cannot be replayed exactly:** it is none at the first factor, then MC64 computed once and reused. Each sequence was therefore replayed with scaling none and with matching on every step.

## Defaults chosen and why

`solver/src/smf_ma97_plugin.cpp` keeps every IPM feature off by default; the env flags stay as opt-ins.

1. **Abort: off.**
   - Held-out: identical logs, but no saving. The aborts skip 0% of the flops, because the excess negatives appear only in the root front.
   - Tuning: the gate failed on chain (the singular vs wrong-inertia status changes IPOPT's path), and the saving was ≤ 3.6%.
2. **Re-analysis: off.**
   - Held-out: wall geomean 1.017 > 1, from rejected attempts on case2000 and case9241.
   - Tuning: the gate failed on the iteration band, and its wins were path changes.
   - It would stay off even if the held-out gate had passed: a feature that failed its tuning gate stays off.
3. **Static mode: Off.**
   - Regularized fails the held-out outcome gate (iterations +23%, wall 4.7×).
   - Fallback fails it (a new failure, iterations 2.75×).
   - Both all-zero variants have new failures.
   - The spec's rule (Regularized if it passes, else Fallback, else Off) gives Off.

## Measurement notes

- **Setup:** IPOPT 3.14.20 through the MA97-ABI plugin, 1 thread (OMP/MKL = 1), below-normal priority. Wall time is the whole IPOPT process.
- **Repetitions:**
  - smf, smf_abort and smf_reanalyse ran 3 times, and the gates use the median IPOPT wall and factorization times (`ipm_gates.merge_repeats`; per-run values are kept as `*_runs` in the JSON).
  - Iterations and objectives were identical across the 3 runs (`repeats_consistent`).
  - MA27 ran once.
  - The four static variants ran **once** (`repeats: 1`). Repetition 1 took 29 minutes, mostly on case9241: fallback ran to max_iter in 589 s, reg_zero hit the 900 s timeout, reg took 62 s. Their gates fail on iteration counts and new failures, which are deterministic in single-thread runs, so repeating them could not change the verdict. This departs from the plan to run every smf* variant 3 times, to keep the machine free.
- **Do not compare absolute times across result files.** The same solver on the same model ran 15–41% slower in the Task 14 session (`ipm_heldout_t1.json`) than in the Phase 0 baseline session (`ipopt_hard_baseline_t1.json`): MA27 1.25–1.41×, smf 1.15–1.30× IPOPT wall, about 30% for both. Only ratios within one file are meaningful, and those are what the gates use.
- **smf vs MA27 on the held-out baseline** (median): smf is slower on the PGLib cases (case9241 15.9 s vs 11.4 s; case2000 2.43 vs 1.68 s). It is faster on polygon (1.45 vs 1.66 s) and on rocket (0.121 vs 0.144 s; both under 1 s, so within noise). Objectives agree to ≤ 1e-14 relative.

## Rulings and spec deviations

Where this work departs from the spec (`docs/superpowers/specs/2026-10-26-ipm-mode-design.md`), and what was done instead:

1. **Regularized row classification.** Spec: a constraint row has a zero *or negative* structural diagonal. Implemented: only a zero or missing diagonal is a constraint row; a negative one is a primal row (an IPOPT primal row is W + Σ + δ_x, which can be negative where W is indefinite; IPOPT's constraint rows carry −δ_c, exactly 0 until a correction). Classes are frozen at the first factorization of each analysis. On the two held-out models with corrections the classes match IPOPT's blocks exactly (Feature 3, "Why both static modes are slow").
2. **Inertia accounting of static pivots.** Spec: every raised pivot is reported as a zero eigenvalue. Implemented: hybrid accounting by default (a pivot raised from an exact zero counts as zero, one raised from a nonzero value by its kept sign), the spec's rule behind `IpmControl::static_as_zero` / `SMF_IPM_STATIC_ZERO=1`. Evidence: with the spec's rule, cops_elec_200 fails ("Error in step computation" at iteration 77, smf_fallback_zero), because constraint pivots near −1/δ_x get raised against a tolerance that grows with δ_x and are reported as zeros that δ_c cannot lift. On the held-out set the all-zero variants then had 4 (Fallback) and 1 (Regularized) new failures.
3. **Wall-time floor in the outcome gate.** Spec: wall geomean ≤ 1 over the models. Implemented: only models whose base IPOPT wall time is ≥ 1 s enter the wall mean, because sub-second runs swing by ±10% between identical runs. Without the floor, re-analysis's held-out wall geomean is 1.0099 (all 6 models), still > 1: still FAIL.
4. **Repetitions.** smf, smf_abort and smf_reanalyse ran 3 times and the gates use the median times; MA27 and the four static variants ran once (their verdicts rest on iterations and failures, which are deterministic at one thread).
5. **A feature that failed its tuning gate stays off,** even if its held-out gate passes. (None passed its held-out gate, so this changed no default.)
6. **`IpmControl` defaults.** Spec struct: `abort_on_wrong_inertia = true` (and `reanalyse`, added next to it, was true). Both are now `false` in `solver/include/smf/ipm_session.hpp`, matching the measured decision; the spec's struct literal is superseded.
