# IPM Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a hard-NLP benchmark corpus, then an engine-level `smf::IpmSession` with early abort on wrong inertia, re-analysis from the realized pivot order, and static/regularized modes. Each feature is gated by measurements on that corpus.

**Architecture:** Phase 0 is Python tooling around IPOPT (`tools/bench/`) plus trace output in the MA97 plugin. Phase 1 adds three small engine hooks (`Control`/`Info`, `multifrontal_serial.cpp`, `symbolic_analysis.cpp`, `supernode_detection.cpp`). Then `IpmSession` (`solver/src/ipm_session.cpp`) wraps `Solver` and owns all IPM policy. The MA97 plugin becomes a thin adapter over it.

**Tech Stack:** C++20, CMake/MSVC, GoogleTest, Python 3 (the `smfbench` conda env: Pyomo, IPOPT 3.14, Egret), unittest.

**Spec:** `docs/superpowers/specs/2026-10-26-ipm-mode-design.md`

Gates: early abort must leave IPOPT logs identical, and stays off by default if it saves < 5% everywhere; re-analysis and static modes need iterations within ±5% (geometric mean), no new failures, and equal-or-better wall time.

## Review Focus

1. **A solve arrives after an aborted factorization** (a caller that ignores inertia). Expected: the session completes the factorization of the same values, and the solve is correct. Test in Task 10.
2. **The pattern changes mid-run** (a new `ma97_analyse` with a different n or pattern). Expected: learned inertia, the probation state and the regularization row classes all reset. Tests in Tasks 9 and 10.
3. **A singular KKT** (IPOPT expects MA97 flag 7) before any factorization has been accepted. Expected: no abort while the expectation is unknown; zero pivots are still reported as `num_zero`, so the plugin still returns flag 7. Test in Task 10.
4. **Regularized mode on a matrix with structurally missing diagonals, or with negative primal diagonals** (nonconvex W). Expected: missing diagonals are added to the analysed pattern. Rows are classified once, at the first factorization of the analysis: a zero or missing diagonal means a constraint row; a negative value means a primal row. Test in Task 13.
5. **Tree-parallel engine (`num_threads > 1`) with the abort armed.** Expected: no hang and no leaked contribution blocks. The factor is identical to the unarmed run when the limit is not exceeded. Test in Task 6.
